Guion corto para la demostración

  1. Resumen: cifras animadas y PieChart; alternar “Por medio” / “Por concepto” (el segundo usa una consulta JPQL con GROUP BY).
  2. Pagos: registrar una tarjeta en 3 cuotas → aviso verde. Intentar pagar de nuevo la matrícula de Lucía → PagoDuplicadoException. Escribir -500 → MontoInvalidoException (el campo se sacude).
  3. Registrar una transferencia: queda “Pendiente”; botón Acreditar. Mostrar Anular y el filtro por medio.
  4. Estudiantes: TreeView con la cuenta corriente. Beca de 150 % → BecaNoAplicableException; beca de 40 % → baja el saldo.
  5. Bitácora: cada operación anterior registrada por el Logger Singleton, también en el archivo.
  6. Simulador de becas (Swing) y por último mvn test.

ArchivoPara qué sirve
Raíz del proyecto
pom.xmlConfiguración de Maven: dependencias (JavaFX, Hibernate, MySQL, H2, JUnit 5) y plugins para ejecutar.
sql/pagos_aranceles.sqlCrea la base y las tablas, carga datos de ejemplo y trae UPDATE y SELECT de control.
config/db.properties.ejemploPlantilla con URL, usuario y contraseña de MySQL (se copia como db.properties).
README.mdPresentación del proyecto y cómo ejecutarlo.
com.ipesmi.pagos
Main.javaLanzador: llama a Application.launch (sirve para ejecutar fuera de Maven/NetBeans).
App.javaAplicación JavaFX: carga Main.fxml y el CSS, dimensiona la ventana y cierra JPA al salir.
model — entidades JPA
Estudiante.javaLegajo (PK), nombre, apellido, email, % de beca y si está activo.
Concepto.javaCódigo (PK), descripción, monto, tipo, si es becable y vencimiento.
Pago.javaClase abstracta: estudiante, concepto, fecha, monto, estado y referencia. Herencia SINGLE_TABLE.
PagoEfectivo.javaPago en caja; la referencia es el número de recibo.
PagoTarjeta.javaPago con tarjeta: últimos 4 dígitos y cantidad de cuotas.
PagoTransferencia.javaTransferencia: número de operación y banco de origen.
EstadoPago / MedioPago / TipoConceptoEnums: Pendiente/Acreditado/Anulado, Efectivo/Tarjeta/Transferencia, Matrícula/Cuota/Examen/Otro.
dao — acceso a datos
JPAUtil.javaCrea un único EntityManagerFactory y arma la configuración (persistence.xml, db.properties, modo demo).
GenericDAO.javaCRUD genérico: guardar, actualizar, eliminar, buscar y listar, con transacciones.
EstudianteDAO / ConceptoDAOListados ordenados con JPQL.
PagoDAO.javaJPQL: pagos con JOIN FETCH, conteos y total acreditado por tipo de concepto (GROUP BY).
service — lógica de negocio
EstudianteService.javaABM de estudiantes con validaciones; HashMap<Integer, Estudiante>.
ConceptoService.javaABM de conceptos y validación de montos.
PagoService.javaRegistrar, editar, acreditar, anular y eliminar pagos; becas; saldos; datos del PieChart. ArrayList<Pago>.
CalculadoraSaldos.javaFórmulas puras: importe con beca, saldo por concepto, saldo total y monto disponible.
AppContext.javaCrea los servicios una sola vez y los comparte entre los controladores.
DatosDemo.javaCarga los datos de ejemplo del script cuando se usa el modo demo (H2).
factory · exception · util
PagoFactory.javaPatrón Factory: crea la subclase de Pago según el medio, valida sus datos y fija el estado inicial.
SolicitudPago.javaRecord con los datos que recibe la fábrica.
ArancelException.javaBase (checked) de las excepciones de negocio.
PagoDuplicado / MontoInvalido / BecaNoAplicableLas tres excepciones personalizadas que pide la consigna.
LoggerTransacciones.javaPatrón Singleton: registra cada transacción y error con fecha y nivel en el archivo de log.
Formatos.javaFormato de pesos y fechas (es-AR) y lectura de montos como “45.000,50”.
